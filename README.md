**v1.7**

把 **Nmap**、**SQLMap**、**DirSearch** 三个命令行工具包成网页上的可视化任务 —— 不用记复杂命令，在页面上点一点就能运行、看实时输出，还能查已知漏洞、让 AI 解读结果并给下一步建议。

## 快速开始

### 方式一：直接用发布包（推荐）

1. 把压缩包**完整解压**到一个文件夹（不要在压缩包里直接双击，会报错）

4. 右上角「AI 设置」→ 选一个供应商 → 填上你自己的 **API Key** → 保存

    pip install -r requirements.txt
    python app/run.py

如果机器上装了 Python 但项目里没有 `runtime/`，启动脚本会自动回退到系统 Python。

## 三个工具是干什么的

本项目的核心，就是把这三个工具「翻译」成中文图形界面。按使用顺序说明。

### 1. Nmap —— 侦察：目标开了哪些端口

**用途**：先搞清楚目标机器上开了哪些端口、跑着什么服务、什么版本。这是所有后续测试的起点。

**典型输入**：IP 或域名，例如 `192.168.1.10`、`example.com`

**界面上的参数（常用）**：

| 选项 | 含义 |
|---|---|
| 预设模板 | 一键组合，见下表 |
| 端口范围 | 只扫指定端口，如 `80,443` 或 `1-1000` |
| 扫描技术 | `-sS` SYN 扫描（快、隐蔽，需管理员权限）/ `-sT` TCP 连接（无需权限）/ `-sU` UDP |
| 时序模板 | `-T0`~`-T5`，数字越大越快、越容易被发现。一般用 `-T4` |
| NSE 脚本 | 调用 Nmap 脚本引擎，如 `vuln`（漏洞检测）、`default` |
| 服务识别 | `-sV` 探测服务版本 |
| 系统探测 | `-O` 推测操作系统 |
| 禁 ping | `-Pn` 目标禁 ping 时必开，否则会误判为「主机不在线」 |
| 详细 | `-v` 输出更详细 |

**预设模板**：

| 预设 | 实际命令 | 适用场景 |
|---|---|---|
| 基础扫描 | `-sV -sC -T4` | 最常用，版本 + 默认脚本 |
| 快速扫描 | `-T4 -F` | 只扫常见 100 个端口，快 |
| 全端口 | `-p- -sV -T4` | 扫全部 65535 端口，慢但全 |
| 服务识别 | `-sV -sC -T4` | 重点看服务版本 |
| 系统探测 | `-O -sV --osscan-guess` | 猜操作系统 |
| 漏洞脚本 | `-sV --script=vuln` | 跑漏洞检测脚本 |
| 隐蔽扫描 | `-sS -T2 -f` | 慢速 + 分片，规避检测 |
| UDP 扫描 | `-sU -sV` | 扫 UDP 服务（DNS、SNMP 等） |

> 选**预设**时，界面上的「端口 / 时序 / -sV / -sC」会被忽略（避免参数重复），预设已经包含了。

**输出怎么看**：关注 `open` 的端口和后面的服务版本。有 80/443 → 下一步用 DirSearch；有数据库端口（3306/1433/5432）→ 考虑 SQLMap；有 22/3389 → 可考虑弱口令测试。

> 💡 **想做漏洞检测，建议用带 `-sV` 的预设**（基础扫描 / 服务识别），这样能拿到版本号去查 NVD。

### 2. DirSearch —— 枚举：网站藏着哪些路径和文件

**用途**：用字典去「猜」网站上有哪些目录和文件，比如 `/admin/`、`/backup.zip`、`/config.php`、`/.git/`。很多敏感文件不会有链接指向它，只能靠猜。

**典型输入**：完整 URL，例如 `http://192.168.1.10/`

**界面上的参数（常用）**：

| 选项 | 含义 |
|---|---|
| 扩展名 `-e` | 只扫这些后缀，如 `php`、`php,html,js`。留空用默认 |
| 字典 `-w` | 自定义字典路径。留空则用内置字典（约 3.9 万条） |
| 请求方法 `-m` | GET / POST / HEAD |
| 线程数 `-t` | 并发数，默认 10。太高容易被封，太低慢 |
| 延迟 `--delay` | 每个请求间隔秒数，如 `0.5`。用于规避限速 |
| 包含状态码 `-i` | 只显示这些状态码，如 `200,301,302` |
| 排除状态码 `-x` | 过滤掉这些，如 `404,500` |
| 排除大小 | 过滤掉特定响应大小的结果，如 `0B`（空页面） |
| 启用递归 | 见下方说明 |
| 强制扩展名 `-f` | 每个路径都追加扩展名 |
| 跟随重定向 `-F` | 跟随 301/302 跳转 |
| Cookie / UA / 代理 | 需要登录态或隐藏来源时填 |

**关于递归**：

- **勾选「启用递归」** 才会递归；不勾就完全不递归
- 递归深度填 **大于 0 的数字** → 递归该层数（`-R 2` 表示递归 2 层）
- 递归深度填 **0 或留空** → 无限递归（`-r`）

**输出怎么看**：重点找敏感文件（`/.env`、`/config.*`、`/backup.*`、`/.git/`、日志文件）、管理入口（`/admin`、`/login`、`/upload`），以及**带参数的 URL**（`?id=`、`?page=`）—— 后者是 SQLMap 的候选目标。

> ⚠ **注意**：本项目附带的是**社区增强版** DirSearch，除原版参数外还有 `--bypass`（403 绕过）、`--jsfind`（JS 里找接口）等增强参数。这些未做进图形界面，需要时可在「附加参数」里手填。

### 3. SQLMap —— 验证：接口是否存在 SQL 注入

**用途**：自动检测并利用 SQL 注入漏洞。能判断某个参数是否可注入、是哪种注入、能拖出哪些数据。

**典型输入**：带参数的 URL，例如 `http://example.com/news.php?id=1`

**界面上的参数（常用）**：

| 选项 | 含义 |
|---|---|
| 注入方式 | 见下表 |
| HTTP 方法 | GET / POST |
| Cookie / UA / 代理 | 需要登录态时填 Cookie |
| `--batch` | 全自动，不询问。**默认开启**，建议保持 |
| `--risk` | 风险等级 1~3，越高 payload 越激进。**默认用 1** |
| `--level` | 检测等级 1~5，越高测的注入点越多、越慢。**默认用 1** |
| `--technique` | 指定注入技术，如 `BEUSTQ`（默认全试） |
| `--tamper` | 绕过 WAF 的脚本，如 `space2comment`、`between` |
| `--threads` | 并发线程数 |
| `--dbms` | 指定数据库类型，跳过自动识别，更快 |
| 枚举操作 | `--dbs` 列库 / `--tables` 列表 / `--columns` 列 / `--dump` 拖数据 / `--current-user` / `--passwords` |
| 指定库表 | `-D 库名 -T 表名`，配合 `--dump` 精确拖某张表 |

**注入方式**：

| 方式 | 实际参数 | 说明 |
|---|---|---|
| URL | `-u <目标>` | 最常用，目标就是带参数的 URL |
| 请求文件 | `-r <文件>` | 从 Burp 等工具导出的请求包测试，能覆盖复杂请求 |
| 批量 URL | `-m <文件>` | 文件里每行一个 URL，批量测 |
| POST 数据 | `-u <目标> --data "<数据>"` | 测试 POST 表单 |
| 爬取注入 | `-u <目标> --crawl <深度>` | 自动爬站找注入点 |

**推荐流程**：先 `--dbs`（列库）→ 再 `-D 库名 --tables`（列表）→ 再 `-D 库名 -T 表名 --dump`（拖数据）。比一上来就 dump 稳妥得多。

## 三个工具怎么串起来用

界面的「轨迹」页把这套流程做成四个阶段：

    Nmap 侦察  →  DirSearch 枚举  →  SQLMap 利用  →  AI 分析
    （开了哪些门）  （有哪些入口）    （哪个入口有洞）  （汇总 + 下一步建议）

**一个典型流程**：

1. **Nmap** 扫 `192.168.1.10` → 发现 80 端口开放，是 Apache 2.4.49
2. **DirSearch** 扫 `http://192.168.1.10/` → 发现 `/news.php?id=1` 和 `/admin/`
3. **SQLMap** 测 `http://192.168.1.10/news.php?id=1` → 确认可注入，拖出用户表
4. **AI 解读** → 汇总发现，给出下一步建议

每步做完，可在轨迹页点「AI 记录此阶段」，让 AI 基于**这一步的真实输出**生成小结与下一步引导。**这些只是建议，不强迫照做**。

## 漏洞检测（轨迹页底部）

跑完扫描后，你可能想知道：**这些结果里有哪些已知漏洞或风险点？**

轨迹页最底部有「漏洞检测」面板，**勾选要检测的任务**，点「开始检测」即可。

### 检测依据（按工具区分）

| 工具 | 检测方式 | 数据来源 |
|---|---|---|
| **Nmap** | 提取产品 + 版本 → 查询 NVD | ✅ NVD 官方数据库（真实 CVE） |
| **DirSearch** | 规则匹配（路径特征） | 内置规则表 → 直接给风险结论（CWE） |
| **SQLMap** | 规则匹配（注入特征） | 内置规则表 → 直接给风险结论（CWE） |
| 都没命中 | **AI 补充分析** | AI 模型知识（标注「AI 推测」） |

**为什么 DirSearch / SQLMap 不给 CVE 编号？**

因为它们输出的是**路径**和**注入结果**，里面没有「产品 + 版本」这种能精确对应 CVE 的信息。硬套一个 CVE 编号反而会误导，所以用 **CWE（通用弱点枚举）** 归类更可靠。

### DirSearch 会识别的风险（部分）

| 特征 | 提示 |
|---|---|
| `/.git/`、`/.svn/` | 源码泄露（CWE-538） |
| `/.env` | 环境变量文件泄露，常含数据库口令、API 密钥 |
| `config.*` | 配置文件暴露（CWE-200） |
| `*.bak` / `*.zip` / `*.sql` | 备份文件暴露（CWE-530） |
| `/admin`、`/manage` | 管理后台入口（CWE-284） |
| `phpinfo.php` | PHP 信息页暴露 |
| `*.log` | 日志文件暴露（CWE-532） |
| `/upload` | 文件上传入口（注意 CWE-434） |
| `robots.txt` | 可能暴露敏感目录 |

### SQLMap 会识别的风险（部分）

| 特征 | 提示 |
|---|---|
| `is vulnerable` | SQL 注入确认（CWE-89） |
| `Parameter: xxx` | 注入参数定位 |
| `back-end DBMS` | 数据库类型识别 |
| `current user` | 数据库账号信息 |
| `password` / `hash` | 凭据泄露（CWE-522） |
| `DBA` | 数据库高权限（CWE-250） |

### 注意事项

- **Nmap 需要版本号**：没开 `-sV` 的话拿不到版本，查不了 NVD
- **NVD 有限流**：匿名访问约 6.5 秒/次，查多个产品需要等待
- **结果仅供参考**：命中说明「该版本存在这个已知漏洞的记录」，**不代表目标一定可被利用**
- **需要联网**（NVD 查询部分）

### 关于两个「启动器」

`runtime/run_dirsearch.py` 和 `runtime/run_sqlmap.py` 不是多余的。**便携版 Python 的模块搜索路径不包含脚本所在目录**，直接运行 `dirsearch.py` / `sqlmap.py` 会因为找不到自己的 `lib` 包而报错：

- dirsearch → `ModuleNotFoundError: No module named 'lib'`
- sqlmap → `[!] wrong installation detected (missing modules)`

启动器的作用就是先把工具目录加进 `sys.path`，再运行它。**所以工具路径配置里要指向启动器，而不是工具的原始 .py 文件。**

## 常见问题

**Q：双击启动脚本提示「请先解压」？**

A：这是防呆处理。请先把压缩包完整解压到文件夹，再双击里面的 `启动控制台.vbs`。

**Q：DirSearch 报 `dicc.txt does not exist`？**

A：字典文件丢了。检查 `tools/dirsearch/db/dicc.txt` 是否存在（应为 385KB 左右）。若缺失，可从 dirsearch 官方仓库的 `db/` 目录取回。**打包分发前请务必确认这个文件在包里。**

**Q：SQLMap 报 `[!] wrong installation detected (missing modules)`？**

A：工具路径没指向启动器。去「工具路径」把 SQLMap 改回 `runtime/run_sqlmap.py`（或点恢复默认）。

**Q：Detected 检测时提示「未识别出可查询的产品/版本特征」？**

A：说明扫描输出里没有产品版本信息。请用带 `-sV` 的 Nmap 预设重新扫一次。

**Q：AI 解读报 `403 无权访问模型 xxx`？**

A：这是**你的 AI 服务商**返回的，不是本项目的问题。说明 API Key 未被开通该模型权限，或模型名不对。去服务商后台确认可用模型列表。

**Q：窗口变窄后布局乱了？**

A：已做响应式适配（1024 / 768 / 520 三档断点）。

**Q：可以扫描公网目标吗？**

A：**只在你拥有明确书面授权的情况下**。未经授权的扫描在绝大多数国家和地区都是违法的。

## 打包与分发注意

**发布包必须包含 `tools/` 与 `runtime/` 两个目录**，否则对方无法直接运行。

打包前建议检查以下文件是否都在：

    tools/dirsearch/db/dicc.txt        ← 最容易漏（字典）
    tools/dirsearch/403list.txt        ← 空文件也要在（程序会读）
    tools/dirsearch/bypass403_url.txt  ← 空文件也要在
    tools/dirsearch/jsfind403list.txt  ← 空文件也要在
    tools/dirsearch/dirsearch.py
    tools/sqlmap/sqlmap.py
    tools/nmap/nmap.exe
    runtime/python/python.exe
    runtime/run_dirsearch.py
    runtime/run_sqlmap.py
    app/main.py
    app/frontend/index.html
    启动控制台.vbs

> ⚠ `403list.txt` / `bypass403_url.txt` / `jsfind403list.txt` 这三个文件**即使内容为空也必须存在**，否则 dirsearch 启动时会因读不到文件而崩溃。

**关于 Git**：`.gitignore` 里排除了 `tools/` 与 `runtime/`（体积大、各有许可证），所以**不要用 Git 导出/克隆的方式分发**，那样会丢掉这两个目录。请直接用压缩包分发。

## 关于工具与许可证

`tools/` 与 `runtime/` 目录**不纳入 Git 版本库**（见 `.gitignore`），原因：体积大（合计 200MB+），且 Nmap、SQLMap、DirSearch 各有自己的开源许可证，Nmap 对商业集成还有额外限制。

因此：

- **Git 仓库**：只含 `app/` 与启动脚本，需自行准备 `tools/`
- **发布压缩包**：含完整 `tools/` 与 `runtime/`，解压即用

三个工具的许可证请参考各自官方仓库：

- Nmap — https://nmap.org/book/man-legal.html
- SQLMap — https://github.com/sqlmapproject/sqlmap
- DirSearch — https://github.com/maurosoria/dirsearch
