# Intrusion · 渗透测试控制台

把 **Nmap**、**SQLMap**、**DirSearch** 这三个命令行工具包成网页上的可视化任务——不用记复杂命令，在页面上点一点就能运行、看实时输出，还能让 AI 帮你解读结果并给下一步建议。

> ⚠ **免责声明**
> 本项目仅供**已获得明确授权**的安全测试、教学与研究使用。请勿对任何未授权的目标进行扫描或测试，使用者需自行承担全部责任。

## 三个工具是干什么的

本项目的核心就是把这三个工具「翻译」成中文图形界面。下面按**使用顺序**说明。

### 1. Nmap —— 侦察：目标开了哪些端口

**用途**：先搞清楚目标机器上开了哪些端口、跑着什么服务、什么版本。这是所有后续测试的起点，因为「不知道有哪些门」就无从下手。

**典型输入**：
- 目标写 **IP 或域名**，例如 `192.168.1.10`、`example.com`

**界面上的参数（常用）**：

| 选项 | 含义 |
|---|---|
| 预设模板 | 一键组合，见下表 |
| 端口范围 | 只扫指定端口，如 `80,443` 或 `1-1000` |
| 扫描技术 | `-sS` SYN 扫描（快、隐蔽，需管理员权限）/ `-sT` TCP 连接（无需权限）/ `-sU` UDP |
| 时序模板 | `-T0`~`-T5`，数字越大越快、越容易被发现。一般用 `-T4` |
| NSE 脚本 | 调用 Nmap 脚本引擎，如 `vuln`（漏洞检测）、`default`（默认脚本） |
| 服务识别 | `-sV` 探测服务版本 |
| 系统探测 | `-O` 推测操作系统 |
| 禁 ping | `-Pn` 目标禁 ping 时必开，否则会误判为「主机不在线」 |
| 详细 | `-v` 输出更详细 |

**预设模板**：

| 预设 | 实际命令 | 适用场景 |
|---|---|---|
| 基础扫描 | `-sV -sC -T4` | 最常用，版本 + 默认脚本 |
| 快速扫描 | `-T4 -F` | 只扫常见 100 个端口，快 |
| 全端口 | `-p- -sV -T4` | 扫全部 65535 端口，慢但全 |
| 服务识别 | `-sV -sC -T4` | 重点看服务版本 |
| 系统探测 | `-O -sV --osscan-guess` | 猜操作系统 |
| 漏洞脚本 | `-sV --script=vuln` | 跑漏洞检测脚本 |
| 隐蔽扫描 | `-sS -T2 -f` | 慢速 + 分片，规避检测 |
| UDP 扫描 | `-sU -sV` | 扫 UDP 服务（DNS、SNMP 等） |

> 小提示：选**预设**时，界面上的「端口 / 时序 / -sV / -sC」会被忽略（避免参数重复），预设已经包含了。

**输出怎么看**：关注 `open` 的端口和后面的服务版本。有 80/443 → 下一步用 DirSearch；有数据库端口（3306/1433/5432）→ 考虑 SQLMap；有 22/3389 → 可考虑弱口令测试。

### 2. DirSearch —— 枚举：网站藏着哪些路径和文件

**用途**：用字典去「猜」网站上有哪些目录和文件，比如 `/admin/`、`/backup.zip`、`/config.php`、`/.git/`。很多敏感文件不会有链接指向它，只能靠猜。

**典型输入**：
- 目标写 **完整 URL**，例如 `http://192.168.1.10/`、`http://example.com/app/`

**界面上的参数（常用）**：

| 选项 | 含义 |
|---|---|
| 扩展名 `-e` | 只扫这些后缀，如 `php`、`php,html,js`。留空用默认 |
| 字典 `-w` | 自定义字典路径。留空则用内置字典 |
| 请求方法 `-m` | GET / POST / HEAD |
| 线程数 `-t` | 并发数，默认 10。太高容易被封，太低慢 |
| 延迟 `--delay` | 每个请求间隔秒数，如 `0.5`。用于规避限速 |
| 包含状态码 `-i` | 只显示这些状态码，如 `200,301,302` |
| 排除状态码 `-x` | 过滤掉这些，如 `404,500` |
| 排除大小 | 过滤掉特定响应大小的结果，如 `0B`（空页面） |
| **启用递归** | 见下方说明 |
| 强制扩展名 `-f` | 每个路径都追加扩展名 |
| 跟随重定向 `-F` | 跟随 301/302 跳转 |
| Cookie / UA / 代理 | 需要登录态或隐藏来源时填 |

**关于递归（这里有个坑，已修复）**：

- **勾选「启用递归」** 才会递归。不勾就完全不递归。
- 递归深度填 **大于 0 的数字** → 递归该层数（`-R 2` 表示递归 2 层）
- 递归深度填 **0 或留空** → 无限递归（`-r`）

> 早期版本「递归开关」和「深度」是各自独立的，同时给会生成互相冲突的 `-r` 和 `-R`。现已改为联动，两者永远不会同时出现。

**输出怎么看**：重点找敏感文件（`/.env`、`/config.*`、`/backup.*`、`/.git/`、日志文件）、管理入口（`/admin`、`/login`、`/upload`），以及**带参数的 URL**（`?id=`、`?page=`）——后者是 SQLMap 的候选目标。

> ⚠ **注意**：本项目附带的是**社区魔改版** DirSearch，除了原版参数外还有 `--bypass`（403 绕过）、`--jsfind`（JS 里找接口）等增强参数。这些参数没有做进图形界面，需要时可在「附加参数」里手填。

### 3. SQLMap —— 验证：接口是否存在 SQL 注入

**用途**：自动检测并利用 SQL 注入漏洞。它能判断某个参数是否可注入、是哪种注入、能拖出哪些数据（库名、表名、字段、账号密码）。

**典型输入**：
- 目标写**带参数的 URL**，例如 `http://example.com/news.php?id=1`

**界面上的参数（常用）**：

| 选项 | 含义 |
|---|---|
| 注入方式 | 见下表 |
| HTTP 方法 | GET / POST |
| Cookie / UA / 代理 | 需要登录态时填 Cookie |
| `--batch` | 全自动，不询问。**默认开启**，建议保持 |
| `--risk` | 风险等级 1~3，越高payload越激进，越可能影响数据。**默认用 1** |
| `--level` | 检测等级 1~5，越高测试的注入点越多、越慢。**默认用 1** |
| `--technique` | 指定注入技术，如 `BEUSTQ`（默认全试） |
| `--tamper` | 绕过 WAF 的脚本，如 `space2comment`、`between` |
| `--threads` | 并发线程数 |
| `--dbms` | 指定数据库类型，跳过自动识别，更快 |
| 枚举操作 | `--dbs` 列出所有库 / `--tables` 列表 / `--columns` 列 / `--dump` 拖数据 / `--current-user` 当前用户 / `--passwords` 拖密码哈希 |
| 指定库表 | `-D 库名 -T 表名`，配合 `--dump` 精确拖某张表 |

**注入方式**：

| 方式 | 实际参数 | 说明 |
|---|---|---|
| URL | `-u <目标>` | 最常用，目标就是带参数的 URL |
| 请求文件 | `-r <文件>` | 从 Burp 等工具导出的请求包测试，能覆盖复杂请求 |
| 批量 URL | `-m <文件>` | 文件里每行一个 URL，批量测 |
| POST 数据 | `-u <目标> --data "<数据>"` | 测试 POST 表单 |
| 爬取注入 | `-u <目标> --crawl <深度>` | 自动爬站找注入点 |

**推荐流程**：先 `--dbs`（列库）→ 再 `-D 库名 --tables`（列表）→ 再 `-D 库名 -T 表名 --dump`（拖数据）。这样比一上来就 dump 稳妥得多。

**输出怎么看**：注意 `Parameter: xxx (GET)` 和 `Type: ...` 那几行——说明哪个参数可注入、是什么类型。如果拖出了用户名和密码哈希，可以做横向测试（**前提是有授权**）。

## 三个工具怎么串起来用

界面的「轨迹」页把这套流程做成了四个阶段：

    Nmap 侦察  →  DirSearch 枚举  →  SQLMap 利用  →  AI 分析
    （开了哪些门）  （有哪些入口）    （哪个入口有洞）  （汇总 + 下一步建议）

**一个典型流程**：

1. **Nmap** 扫 `192.168.1.10` → 发现 80 端口开放，是 Apache
2. **DirSearch** 扫 `http://192.168.1.10/` → 发现 `/news.php?id=1` 和 `/admin/`
3. **SQLMap** 测 `http://192.168.1.10/news.php?id=1` → 确认可注入，拖出用户表
4. **AI 解读** → 汇总发现，给出下一步建议（比如「用拖出的账号试试其他服务」）

每一步做完，可以在轨迹页点「AI 记录此阶段」，让 AI 基于**这一步的真实输出**生成小结和下一步引导。**这些只是建议，不强迫照做**——你完全可以根据实际情况走别的路。

## CVE 漏洞检测

扫描完一个目标后，你可能想知道：**这些服务版本有没有已知漏洞？**

轨迹页最底部有「可能的 CVE 漏洞」面板，点 **「检测 CVE」** 按钮就能查。

### 它是怎么工作的

    Nmap 扫描输出
        ↓  程序提取「产品 + 版本」（如 Apache 2.4.49）
    查询 NVD 官方数据库（美国国家漏洞库）
        ↓
    列出真实命中的 CVE（编号 / 评分 / 描述 / 跳转链接）

**关键点：CVE 数据来自 NVD 官方 API，不是 AI 编的。**

AI 不能联网，所以这里让**程序**去查真实数据库——这样漏洞编号、CVSS 评分、描述都是权威数据，而且永远是最新的。

### 怎么用

1. 先跑一次 **Nmap 扫描**，**必须用带 `-sV` 的预设**（「基础扫描」或「服务识别」），否则输出里没有版本信息
2. 切到 **轨迹** 页
3. 拉到底部，点 **「检测 CVE」**
4. 等待查询完成（可能十几秒，原因见下）
5. 看结果卡片，点 **「NVD 详情」** 或 **「CVE.org」** 跳转查看

### 结果怎么看

每张卡片包含：

| 字段 | 说明 |
|---|---|
| CVE 编号 | 如 `CVE-2021-41773`，点击可跳转官方详情页 |
| 严重程度 | CRITICAL（红）/ HIGH（橙）/ MEDIUM（黄）/ LOW（绿） |
| CVSS 评分 | 0~10 分，越高越严重 |
| 描述 | 漏洞的英文官方描述 |
| 匹配依据 | 是根据哪个「产品 + 版本」匹配到的 |
| 跳转按钮 | NVD 详情、CVE.org 两个来源 |

### 把握度是怎么保证的

为了避免"瞎报"，查询做了三重过滤：

1. **关键词精简**——产品名做清洗（`Apache httpd` → `Apache`），关键词太长反而搜不到
2. **版本号必须出现在描述里**——只有当 NVD 的漏洞描述中**真的提到**这个版本号，才认为是命中；否则可能只是泛泛相关，直接丢弃
3. **限流保护**——NVD 对匿名请求有速率限制（约 6.5 秒/次），代码里做了等待，避免被拒绝

### 注意事项

- **必须有版本信息才查得到**。如果 Nmap 扫描没开 `-sV`，输出里没有版本号，面板会提示"未能识别出可查询的产品/版本特征"
- **查询较慢是正常的**。NVD 匿名访问有速率限制，查 3 个产品大约需要 20 秒。如果需要更快，可以去 NVD 官网申请免费 API Key
- **结果仅供参考**。命中的 CVE 只说明"该版本存在这个已知漏洞的记录"，**不代表目标一定可被利用**——是否真的存在漏洞，需要进一步验证
- **需要联网**。查询依赖 NVD 的公开 API（`services.nvd.nist.gov`），离线环境无法使用

### 与「AI 解读」的区别

| | AI 解读 | CVE 检测 |
|---|---|---|
| 数据来源 | AI 模型的记忆 | NVD 官方数据库 |
| 准确性 | 可能过时、可能编造 | 权威、实时 |
| 需要联网 | 需要（调 AI 接口） | 需要（调 NVD 接口） |
| 输出内容 | 通俗解读 + 修复建议 | 具体 CVE 编号 + 评分 + 链接 |

两者互补：AI 告诉你"这意味着什么、该怎么办"，CVE 检测告诉你"具体是哪个已知漏洞"。

## 常见问题

**Q：双击启动脚本提示"请先解压"？**

A：这是防呆处理。请先把压缩包完整解压到文件夹，再双击里面的 `启动控制台.vbs`。

**Q：AI 解读报 `403 无权访问模型 xxx`？**

A：这是**你的 AI 服务商**返回的，不是本项目的问题。说明你的 API Key 未被开通该模型权限，或模型名不对。去服务商后台确认可用模型列表。

**Q：窗口变窄后布局乱了？**

A：已做响应式适配（1024 / 768 / 520 三档断点）。

**Q：点「检测 CVE」没反应 / 提示"未能识别出可查询的产品/版本特征"？**

A：说明扫描输出里没有产品版本信息。请用带 `-sV` 的 Nmap 预设（「基础扫描」或「服务识别」）重新扫一次，再用 CVE 检测。

**Q：CVE 检测很慢？**

A：NVD 对匿名请求有速率限制（约 6.5 秒/次），查多个产品时需要等待，属正常现象。想要更快可以在 NVD 官网申请免费 API Key。

**Q：可以扫描公网目标吗？**

A：**只在你拥有明确书面授权的情况下**。未经授权的扫描在绝大多数国家和地区都是违法的。

## 关于工具与许可证

`tools/` 和 `runtime/` 目录**不纳入 Git 版本库**（见 `.gitignore`），原因：体积大（合计 200MB+），且 Nmap、SQLMap、DirSearch 各有自己的开源许可证，Nmap 对商业集成还有额外限制。

因此：

- **Git 仓库**：只含 `app/` 与启动脚本，需自行准备 `tools/`
- **发布压缩包**：含完整 `tools/` 与 `runtime/`，解压即用

三个工具的许可证请参考各自官方仓库：

- Nmap — https://nmap.org/book/man-legal.html
- SQLMap — https://github.com/sqlmapproject/sqlmap
- DirSearch — https://github.com/maurosoria/dirsearch
